---
title: "Upload Claim Receipt"
openapi: "POST /api/auth/v1/claims/receipts/"
description: "Upload the receipt a practice printed for the patient"
---

Some insurers, such as EyeMed, take an itemized receipt from the practice together with the claim. To send the receipt the practice printed for the patient, upload its files with this endpoint before creating the claim, one file per request. Then pass the returned `upload_uid` values in `receipt_upload_uids` to the [Create Claim](/api-reference/endpoint/create_claim) endpoint, in the order the files go into the claim. The claim is created with the receipt already attached, and it goes out instead of the receipt Anagram builds from the template of the claim's location.

The request body must be JSON, with the file in the `content` field encoded in standard base64, without line breaks:

- a PDF of up to 10 pages, or a PNG or JPG image of up to 50 megapixels
- 15 MB at most

A claim takes up to 5 files, with up to 15 MB and 20 pages in total. See [Receipt](/api-reference/endpoint/create_claim#receipt) for how they are counted.

The file type is detected from the file itself, not from `filename`. A PDF is attached to the claim as it is, and an image is placed on a letter-size page.

An upload belongs to your practice and can be attached to one claim only. An upload that no claim takes within a day expires. If a claim is not created because of a validation error, its uploads stay available and can be passed again.

A practice can upload up to 60 files a minute and keep up to 100 uploads that no claim has taken yet. The limits count files, not claims: a claim with 3 files takes 3 uploads. Above that, the endpoint responds with `429 Too Many Requests`. Files uploaded in the Anagram App count toward both limits.
